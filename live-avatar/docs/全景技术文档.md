## 1. 系统概览

一套**平台无关**的直播虚拟形象与弹幕互动系统：透明背景的大肥鱼悬浮在直播画面上，观众通过弹幕触发动作/点歌/进场问候，主播拥有监控台与点歌台。核心不知道任何直播平台的存在，通过适配器对接具体平台——**换推流软件或弹幕平台，只换适配器，核心零修改**。

能力清单：

- 106 个透明 WebM 动作 + 48 组关键词别名点播 + 7 组连招（组合动作）
- 观众进场自动打招呼（挥手/女仆礼，独立冷却）
- 弹幕点歌：B 站搜索 → 选片（录音棚>现场、原唱>翻唱）→ 浏览器播放（A 模式）或自建点歌台（B 模式）自动切换
- 主播监控台：同步形象 + 16 免冷却按钮 + 实时弹幕流 + 状态灯
- 自建点歌台：内嵌 B 站播放器 + 队列管理 + 自动切歌
- 三种推流软件挂载方式：浏览器源 / 色键抠像（`?bg=green`）/ 整屏采集
- 纯 Python 标准库 + 原生 HTML/JS，核心零第三方依赖

## 2. 总体架构

```
                      ┌───────────────────── 平台无关核心 avatar/ ─────────────────────┐
                      │  danmaku_hub.py                                              │
                      │   :8642 HTTP 静态服务 + /api/status 健康接口                    │
                      │   :8643 WebSocket 事件总线（手写 RFC6455 实现）                 │
                      │   关键词引擎（别名/连招/进场问候/冷却/去重）                      │
                      └──────▲──────────────▲──────────────────▲────────────────────┘
                             │ ws           │ ws               │ ws
              ┌──────────────┴───┐   ┌──────┴────────┐   ┌──────┴──────────────┐
              │ danmaku_bilibili │   │ jukebox_bilibili│  │ 页面客户端           │
              │ B站弹幕适配器     │   │ B站点歌适配器    │  │ index.html 直播形象  │
              │ TCP 2243+WBI签名 │   │ 搜索选片+播放    │  │ console.html 监控台 │
              └──────────────────┘   └────────────────┘   │ jukebox.html 点歌台 │
                                                          └─────────────────────┘
推流软件（OBS / 任何软件）──浏览器源或色键──挂载 index.html
```

## 3. 组件详解

### 3.1 互动核心 danmaku_hub.py

| 项 | 说明 |
|---|---|
:---|:---
| 进程模型 | 主线程=关键词引擎（阻塞队列）；守护线程×3：HTTP 服务、总线 accept 循环、每客户端读写线程 |
| WebSocket | 手写 RFC6455：Upgrade 握手、文本帧解析、客户端帧掩码解除、ping/pong |
| 健壮性 | hub 侧 socket 统一 15 秒超时——僵尸客户端最多阻塞广播 15 秒即被剔除；空闲合法客户端 recv 超时被吞掉不断开 |
| `/api/status` | HTTP GET 返回 `{"danmaku_online","popularity","roomid"}`，供启动脚本/巡检做健康判断 |
| 引擎 | 事件队列 → 匹配（动作全名 > 别名表 > 连招表）→ 冷却（观众 5s / 进场问候独立 8s）→ 广播 |

### 3.2 B站弹幕适配器 danmaku_bilibili.py

- **连接方式**：裸 TCP `broadcastlv.chat.bilibili.com:2243`（老协议）。不走 443 WSS——B 站 2024+ 对弹幕服务启用 TLS 指纹风控，Python/Node 的 TLS 握手能通过但认证即被断，浏览器内核也仅存活到认证；TCP 老端口无此问题（实测长期稳定）
- **认证**：WBI 签名调 `getDanmuInfo` 拿一次性 token（签名算法：img_key+sub_key 按固定混淆表取前 32 字符为 mixin，参数排序 urlencode + wts 后 MD5 得 w_rid）；auth 包 `{uid, roomid, protover:3, platform:"web", type:2, key:token}`
- **凭据发现**：自动读 Bili Live Hime 的 `%APPDATA%/com.rsplwe.bili-live-hime/app-config.json`（cookies/img_url/sub_url/roomId）；也支持 `--roomid` `--cookies` 手动指定
- **消息解压**：protover 3 = brotli（`pip install brotlicffi`，未装自动降级 protover 2 = zlib）
- **事件**：DANMU_MSG（弹幕）、INTERACT_WORD（进场，msg_type=1）、ENTRY_EFFECT（大航海进场）→ 上报总线
- **重连**：指数退避 10s→600s 封顶；token 每次重连刷新；对总线侧断链自愈（连发 10 次失败即重建）

### 3.3 点歌适配器 jukebox_bilibili.py

**选片算法（两级）**：

```
准入过滤：时长 1~10 分钟；标题含（舞蹈/翻跳/教学/混剪/游戏/综艺…）淘汰
优先级（依次比较）：
  1 音乐区且标题含歌名      （音乐区 = 分区名含"音乐" 或 分区名=="MV"）
  2 音乐区
  3 标题含歌名
  4 无负面词
  5 录音棚/无损/MV 优先     （标题含：录音棚/Hi-Res/无损/专辑/MV；现场词：现场/LIVE/演唱会/直拍/纯享/TOUR）
  6 原唱信号               （点歌带歌手名如"大鱼 周深"时，标题含歌手优先）
  7 翻唱/串烧降权          （翻唱/cover/串烧/填词/改编/钢琴版…）
  8 B站综合排序位次（兜底，相关性由B站自己保证）
```

踩坑教训（都已修）：分区名"MV"不含"音乐"二字导致官方 MV 被判非音乐区（大香蕉猫咪版/平凡之路串烧事故）；时长接近 4 分钟的偏好会压过内容质量（起风了选中翻唱现场）。

**A/B 模式自动切换**：点歌台页面每 30 秒经 relay 广播 `jukebox_hello` 心跳；适配器据心跳判断页面在线——在线 → 只广播 `song` 事件由页面播放（B 模式）；离线（>70s 无心跳）→ 本机浏览器开标签（A 模式）。

**防刷**：全局点歌冷却 30s（重连不重置）；同人同歌 60s 去重。

### 3.4 直播形象页 index.html

- 单 `<video>` 播 640×360 透明 WebM；状态机：待机循环 / 单发动作 / 连招队列（`playSequence`，seq 序号防竞态）
- 播放保活：每秒检查 paused 自动恢复（兼容 OBS CEF 冷启动自动播放限制）
- URL 参数：`scale / interval / bubble / roam / pool / bg(色键模式) / hub(隔离测试)`
- 自动行为：每 interval 秒随机表演；开场挥手+欢迎气泡

### 3.5 监控台 console.html

同步形象 + 16 动作按钮（`cmd` 上报，免冷却）+ 🎵点歌按钮（prompt 歌名）+ 实时弹幕流（触发高亮）+ 双状态灯 + 人气值。

### 3.6 点歌台 jukebox.html

- 内嵌 B 站官方 iframe 播放器；队列（当前播放 ▶ / 排队 / 点歌人 / 单曲跳过 / 清空）
- **自动切歌**：iframe 跨域拿不到 ended 事件 → 用搜索所得时长 +8s 定时兜底
- **强制重载**：播放 URL 带 `_r=时间戳`——连续播同一 bvid 时 src 变化触发重载（否则浏览器不重载、连播看似失效）
- **入队去重**：同 bvid 已在播/已在队 → 忽略
- 首次点击解锁层：满足浏览器音频自动播放策略
- `?hub=` 参数支持连隔离总线做冒烟测试

### 3.7 OBS 适配 scripts/setup_obs.py

obs-websocket 5.x 客户端（手写 WS：Upgrade + 客户端帧**必须掩码**）；密码自动从 `%APPDATA%\obs-studio\plugin_config\obs-websocket\config.json` 读取，未启用则自动开启并提示重启 OBS；幂等创建 `monitor_capture`（注意：OBS 33 的显示器采集类型名是 `monitor_capture`，不是旧文档的 `display_capture`）+ 大肥鱼浏览器源。

### 3.8 运维脚本 ops/

检查.bat（体检：端口/HTTP/进程/B站连接/OBS）、重启核心/适配器/全部、刷新OBS形象页（visibility 切换强制重载）、修复OBS场景。bat 统一 **GBK 编码 + CRLF 行尾**（cmd 解析 LF-only 的带标签脚本会错乱；Git Bash 环境跑 GBK bat 需先 `chcp 936`）。

## 4. 事件总线协议（ws://127.0.0.1:8643）

### 客户端 → 核心

| 消息 | 语义 |
|---|---|
| `{"type":"danmaku","user","text"}` | 弹幕事件（3s 同人同文去重后进引擎） |
| `{"type":"cmd","text"}` | 手动触发（监控台按钮，免冷却） |
| `{"type":"enter","user","vip"}` | 观众进场（10s 同人去重，触发问候） |
| `{"type":"source_status","online","roomid","popularity"}` | 弹幕源状态上报 |
| `{"type":"relay","data":{…}}` | **中继通道**：data 原样广播给所有客户端（适配器扩展能力的基础） |

### 核心 → 所有客户端（广播）

| 消息 | 语义 |
|---|---|
| `{"type":"action","name","seq","text","user"}` | 触发动作（seq 存在 = 连招顺序播放） |
| `{"type":"danmaku","user","text","action","state"}` | 弹幕/事件回显（state: 已触发/冷却中） |
| `{"type":"status","danmaku","roomid","popularity"}` | 状态同步（新客户端接入即推） |

### relay 解包约定

核心转发 relay 时**解包**：客户端收到的是 `data` 本体（如 `{"type":"song",…}` 直接出现，外层无 relay 包装）。

## 5. 关键技术决策与踩坑实录

| # | 问题 | 结论 |
|---|---|---|
| 1 | B 站弹幕 443 WSS 全路径被断（Python/Node/浏览器内核全灭） | TLS 指纹风控；走 **TCP 2243 老协议** + WBI 签名 token |
| 2 | getDanmuInfo 返回 -352 | 需要 WBI 请求签名（mixin key 混淆表 + MD5） |
| 3 | OBS 33 建源报"input kind not supported" | 显示器采集类型名已改为 `monitor_capture` |
| 4 | 自写 WS 客户端连 OBS 被拒 code 1002 | 客户端→服务端帧**必须掩码**（RFC6455） |
| 5 | 改 OBS 场景文件不生效且有崩溃恢复弹窗 | OBS 场景集合有崩溃恢复机制，直接改文件易被回滚/弹安全模式；**用 obs-websocket API 操作**；崩溃标记在 `.sentinel/` |
| 6 | 总线广播随机卡死 | 非正常断开的客户端会无限阻塞 sendall 并锁住广播——hub 侧统一 socket 超时 + 剔除 |
| 7 | bat 双击乱码/语法错 | cmd 按 GBK 解析：**GBK 编码 + CRLF 行尾**；`chcp 65001` 在 bat 内有字节偏移 bug |
| 8 | 点歌台连播失效 | iframe src 不变则浏览器不重载——URL 加时间戳强制重载 |
| 9 | 搜索选到猫咪版/串烧 | 分区名"MV"不含"音乐"；时长偏好压过内容质量——MV 并入音乐区 + 综合位次兜底 |
| 10 | 弹幕适配器长期空转 | 长连接数天后 B 站链路静默失效——启动脚本以 `/api/status` 为准做健康检查+换新 |

## 6. 凭据与数据流（安全边界）

```
Bili Live Hime (app-config.json)  ──读──>  两个B站适配器（cookie/WBI key/房间号）
核心/页面                          ──无任何凭据，只处理事件
OBS websocket 密码                 ──读──>  setup_obs / reload_obs_fish（本机 config.json）
推流密钥                           ──只存在于 OBS 与 Bili Live Hime，本系统不接触
```

`.gitignore` 屏蔽 cookies/token/日志/截图；仓库已通过 12 类敏感模式全库扫描。

## 7. 运维体系

- **每次开播**：`scripts/start-toolchain.bat`（5 步：核心 → 弹幕适配器(带 /api/status 健康重试) → 点歌适配器 → 监控台 → OBS，全部幂等跳过已运行项）
- **任何异常**：先 `ops/检查.bat`，按报告箭头用对应重启脚本
- 点歌台：`msedge --app=http://127.0.0.1:8642/jukebox.html`（刷新即清队列重连）

## 8. 扩展开发

**新弹幕平台适配器**（三步）：连平台弹幕 → 每条发 `{"type":"danmaku",...}` 到 :8643 → 启停时发 `source_status`。参考 danmaku_bilibili.py。

**新动作**（三路线）：COMBOS 加连招（零素材）/ 投放 640×360 VP9 yuva420p 透明 WebM + 登记 ANIMS / ffmpeg 转码自制：
```
ffmpeg -framerate 15 -i frame_%03d.png -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 1M -an 新动作名.webm
```

**新总线客户端**：任意语言接 ws://127.0.0.1:8643，收 `action` 即可驱动任意可视化（不限于这只鱼）。
